# AGENTS.md

## Область проекта

На текущем этапе проект начинается с интеграции Todoist.

Todoist является источником истины для задач пользователя.
Локальные файлы в `data/todoist/` — это синхронизированные снимки состояния, которые агент использует для быстрого и надёжного анализа.

Не считать локальные JSON-файлы основной базой задач.

---

## Интеграция Todoist

Интеграция Todoist находится в:

`integrations/todoist/`

Основная команда синхронизации:

```bash
python -m integrations.todoist.sync
```

Команду необходимо запускать из корня проекта.

Во время синхронизации:

1. Загружаются активные задачи Todoist.
2. Загружаются проекты Todoist.
3. Загружаются секции Todoist.
4. Данные нормализуются в одну человекочитаемую структуру.
5. Сохраняется предыдущий снимок состояния.
6. Сохраняется текущий снимок состояния.
7. Создаётся diff между предыдущим и текущим состояниями.

Создаваемые файлы:

```text
data/todoist/
├── tasks.json
├── tasks.prev.json
└── tasks.diff.json
```

---

## Когда нужно синхронизировать Todoist

НЕ запускать синхронизацию Todoist при каждом запросе пользователя.

Синхронизацию необходимо запускать перед ответом, если запрос зависит от текущего состояния задач.

Примеры:

- какие у меня задачи?
- что мне делать сегодня?
- какие задачи просрочены?
- что изменилось в моих задачах?
- чему сейчас отдать приоритет?
- что находится в проекте X?
- добавил или удалил я что-нибудь?
- помоги спланировать работу на основе Todoist;
- вопросы о сроках, дедлайнах, приоритетах, проектах, секциях или подзадачах.

Для запросов, не связанных с актуальным состоянием задач, синхронизацию не запускать.

---

## Обязательный порядок работы с Todoist

Если для ответа нужны свежие данные Todoist:

1. Запустить:

```bash
python -m integrations.todoist.sync
```

2. Дождаться полного завершения команды.

3. Убедиться, что синхронизация завершилась успешно.

4. Сначала прочитать:

```text
data/todoist/tasks.diff.json
```

5. Использовать diff, чтобы понять, что изменилось с предыдущей синхронизации.

6. Если требуется полное текущее состояние задач, прочитать:

```text
data/todoist/tasks.json
```

7. Только после получения необходимых данных отвечать пользователю.

---

## Как использовать tasks.diff.json

`tasks.diff.json` содержит компактное описание изменений между предыдущим и текущим снимками.

Он может содержать:

- `added` — новые задачи;
- `removed_from_active` — задачи, исчезнувшие из списка активных;
- `changed` — изменённые задачи;
- `unchanged` — задачи без изменений.

Использовать этот файл, чтобы не анализировать заново весь список задач, когда важны только последние изменения.

Важно:

`removed_from_active` НЕ означает автоматически `completed`.

Задача может исчезнуть из API активных задач по разным причинам.

Нельзя утверждать, что задача выполнена, если имеющиеся данные этого не доказывают.

---

## Как использовать tasks.json

`tasks.json` содержит полный текущий нормализованный снимок активных задач Todoist.

Каждая задача может содержать:

- ID задачи;
- название;
- описание;
- ID и название проекта;
- ID и название секции;
- ID и название родительской задачи;
- метки;
- приоритет;
- дату выполнения;
- дедлайн;
- длительность;
- информацию о порядке;
- количество переносов;
- временные метки.

Использовать ID для точной идентификации объектов.

Использовать названия и текст задач для рассуждений и ответов пользователю.

Нельзя считать два проекта, две секции или две задачи одинаковыми только потому, что у них одинаковые названия.

---

## Правила работы со снимками состояния

Не редактировать вручную:

```text
data/todoist/tasks.json
data/todoist/tasks.prev.json
data/todoist/tasks.diff.json
```

Эти файлы генерируются автоматически.

Если данные Todoist необходимо изменить, изменение должно происходить непосредственно в Todoist или через отдельную интеграцию для записи в Todoist.

После любых внешних изменений в Todoist необходимо снова выполнить синхронизацию, прежде чем полагаться на локальное состояние.

---

## Обработка ошибок

Если синхронизация Todoist завершилась ошибкой:

- не считать локальные данные свежими;
- не продолжать молча работу так, будто синхронизация прошла успешно;
- явно сообщить, что синхронизация не удалась;
- существующий `tasks.json` можно использовать только как устаревший снимок, если это полезно;
- если используются устаревшие данные, явно сказать, что они могут быть неактуальны.

Никогда не заменять корректный текущий снимок неполными данными после неудачной синхронизации.

---

## Правила обработки данных

Предпочитать детерминированный код для:

- синхронизации;
- нормализации;
- точного сравнения снимков;
- определения добавленных, исчезнувших и изменённых задач.

Использовать LLM для:

- интерпретации;
- расстановки приоритетов;
- планирования;
- создания сводок;
- поиска закономерностей;
- анализа компромиссов;
- определения того, что требует внимания.

Не заставлять LLM самостоятельно выполнять точное сравнение снимков, если результат уже находится в `tasks.diff.json`.

---

## Текущее архитектурное правило

На текущем этапе слой Todoist должен оставаться простым.

Пока:

- SQLite не требуется;
- `tasks.json` — текущий нормализованный снимок;
- `tasks.prev.json` — непосредственно предыдущий снимок;
- `tasks.diff.json` — детерминированная разница между ними.

Не добавлять дополнительное хранилище или инфраструктуру без конкретной необходимости.
